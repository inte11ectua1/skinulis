# Правила работы над «Скинулись»

- Работаем по GitHub Flow: `main` стабильная, для задачи отдельная `feat/T-02-name`, `feat/O-02-name`, `feat/L-02-name` или `docs/...` ветка.
- Все изменения попадают в `main` исключительно через Pull Request, который одобрил минимум один другой участник.
- Используем Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
- В PR указываем issue, изменения, тесты и риски. Приложить результаты команд проверок, если CI ещё не настроен.
- PR с изменением финансовых правил требует согласования Олега; изменения авторизации и инфраструктуры — Тимура; контрактов бота — Леры. Все изменения API-контрактов согласуем заранее.
- Не коммитим `.env`, токены, реальные учётные данные и базы данных.
- Актуальные статусы работ сохраняем в `docs/STATUS.md`; решения — в `docs/` и ADR.
- Конфликты и несовместимые контракты обсуждаем в issue до изменения реализации.

Настройку branch protection (approval, проверка статусов CI, блокировка push) нужно выполнить отдельно в GitHub Settings после появления первого workflow.
