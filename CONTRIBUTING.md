# Правила работы над «Скинулись»

- Работаем по GitHub Flow: `main` стабильная, для задачи отдельная `feat/T-02-name`, `feat/O-02-name`, `feat/L-02-name` или `docs/...` ветка.
- Все изменения попадают в `main` через Pull Request. **Командный стандарт** — approval как минимум одного другого участника; у владельца GitHub сейчас есть административный обход, поэтому для него approval нельзя считать технически гарантированным.
- Используем Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
- В PR указываем issue, изменения, тесты и риски. Приложить результаты команд проверок, если CI ещё не настроен.
- PR с изменением финансовых правил требует согласования Олега; изменения авторизации и инфраструктуры — Тимура; контрактов бота — Леры. Все изменения API-контрактов согласуем заранее.
- Не коммитим `.env`, токены, реальные учётные данные и базы данных.
- Актуальные статусы работ сохраняем в `docs/STATUS.md`; решения — в `docs/` и ADR.
- Конфликты и несовместимые контракты обсуждаем в issue до изменения реализации.

Ожидаемые перед merge проверки: актуальные зелёные `lint`, `types`, `tests`,
`docker-build`, `ci`, минимум одно независимое approval и разрешённые conversations.
Новый коммит запускает CI заново; по правилам защиты может сбрасывать прежнее approval.
Пропущенный job не считается успехом. Не переименовывать checks без обновления branch protection.
**Факт на 27.10.2026:** правила required checks возвращают `enforcement_level=non_admins`, поэтому администраторский обход возможен; он не заменяет доказательства зелёного CI и ревью. Если владелец мержит без approval, явно отмечать это исключение в PR, а не утверждать, что независимый review получен.
Фактические настройки, доказательства и инструкция администратора:
[CI и защита main](docs/operations/CI.md).

## Локальные проверки

Установите окружение по [README](README.md#окружение-разработки), затем включите hooks:

```bash
uv sync --frozen
uv run pre-commit install
uv lock --check
uv run ruff check .
uv run ruff format --check .
uv run mypy .
uv run pytest
uv run pre-commit run --all-files
uv pip check
uv audit --locked
```

При ошибках форматирования выполните `uv run ruff format .`, проверьте diff и повторите
проверки. Команда mypy проверяет весь существующий Python-код, включая тесты; новые
модули попадут в неё автоматически. PostgreSQL integration запускается отдельно командой
`uv run python scripts/test_integration.py`; объединённое branch coverage `app/`
и `bot/` (>=60%) описано в README. Перед PR также выполните `docker build .`.
В PR указывайте реальные результаты локальных проверок и ссылку на успешный
GitHub Actions run для текущего head; до завершения workflow задача не готова.
CI не заменяет review бизнес-логики и ручные проверки ещё не реализованных E2E.
