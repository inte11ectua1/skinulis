- **Статус:** Принято ([PR #7](https://github.com/inte11ectua1/skinulis/pull/7) одобрен Олегом после исправлений и merged 26.10.2026).
- **Дата:** 16 октября 2026 года
- **Ответственный:** Тимур (technical lead)
- **Участники обсуждения:** Тимур, Олег; независимое review Олега зафиксировано в PR #7.
- **Связанная задача:** [T-02, issue #5](https://github.com/inte11ectua1/skinulis/issues/5)

## Контекст и проблема

Три разработчика работают над API, финансовой логикой и Telegram-ботом в одном репозитории. Разные версии Python, прямых и транзитивных зависимостей могут давать разные результаты проверок на компьютерах участников и в будущем CI. Нужны единые команды установки, запуска инструментов и намеренного обновления зависимостей.

Python 3.12 и uv уже предусмотрены [техническими решениями](../TECHNICAL_DECISIONS.md). Этот ADR объясняет выбор и конкретизирует воспроизводимый процесс. В T-02 приложения ещё нет: настройка окружения не подтверждает готовность API, бота, Docker или CI.

## Рассмотренные варианты

| Вариант | Возможности и компромиссы для проекта |
|---|---|
| pip + venv | Стандартный и знакомый подход. Воспроизводимую установку можно организовать фиксированными версиями и хешами в requirements. Подготовку Python, окружения и процесс обновления фиксированных зависимостей придётся согласовать отдельно. [Документация pip](https://pip.pypa.io/en/stable/topics/repeatable-installs/). |
| Poetry | Управляет зависимостями, виртуальным окружением и `poetry.lock`; подходит для такого проекта. Требует собственного установленного CLI и освоения его команд. Его выбор изменил бы уже согласованный инструмент без необходимой нам дополнительной возможности. [Документация Poetry](https://python-poetry.org/docs/basic-usage/). |
| uv | Объединяет управление Python, окружением, зависимостями и запуск команд. `uv.lock` сохраняет разрешённые зависимости. Соответствует принятому направлению стека; выбран для общего процесса команды. [Установка Python](https://docs.astral.sh/uv/guides/install-python/), [lock и sync](https://docs.astral.sh/uv/concepts/projects/sync/). |

## Решение

1. Используем **uv 0.13.5**, требование `required-version = "==0.13.5"` в `pyproject.toml`. Инструкции установки фиксируют эту же версию.
2. `.python-version` закрепляет **CPython 3.12.15**; `requires-python = ">=3.12,<3.13"` ограничивает совместимость проекта семейством 3.12. Обновления patch-версии проходят отдельный PR с повторной проверкой окружения.
3. Прямые зависимости описываем в `pyproject.toml`, разрешённые версии и артефакты — в `uv.lock`. Оба файла храним в Git и меняем совместно. Ручное редактирование lock-файла не используем.
4. Окружение создаём в `.venv`, команды запускаем через `uv run`. Репозиторий — приложение, сейчас без устанавливаемого Python-пакета: `package = false`, build backend пока не нужен.
5. В T-02 группа `dev` содержит Ruff, mypy, pytest, pytest-cov, pre-commit и detect-secrets. Runtime-зависимости добавляются вместе с потребляющими их модулями в последующих задачах.
6. Для воспроизведения выполняем `uv python install`, `uv sync --frozen` и `uv lock --check`. Frozen-установка не проверяет актуальность lock-файла относительно конфигурации; отдельная проверка обязательна. Локальные hooks запускают инструменты с `uv run --locked`, чтобы рассинхронизация завершалась ошибкой.
7. Для новых зависимостей используем `uv add` / `uv add --dev`, для целевого обновления — `uv lock --upgrade-package`. После изменения просматриваем diff обоих файлов и повторяем проверки из [README](../../README.md).

### Уточнение по ревью от 26 октября 2026 года

Версия uv обновлена с 0.13.1 до 0.13.5: [GHSA-hq85-5cpj-mr62](https://github.com/astral-sh/uv/security/advisories/GHSA-hq85-5cpj-mr62) затрагивает версии до 0.13.4. Выбран следующий patch-релиз 0.13.5, который также обновляет сборки managed Python. Для существующего рабочего места сборку закреплённого Python переустанавливаем через `uv python install --reinstall`; версия Python остаётся 3.12.15. [Описание релиза](https://github.com/astral-sh/uv/releases/tag/0.13.5).

Уязвимые транзитивные зависимости `certifi`, `filelock`, `virtualenv` обновляются целевым разрешением через uv. Исключения уязвимостей и ручное редактирование lock-файла не применяются. Известное ограничение установки Python на Windows и порядок повторной проверки указаны в README. PR #7 принят; статус ADR обновлён как «Принято». Ограничение Windows остаётся открытым, несмотря на согласование решения.

## Преимущества

- Одинаковые зафиксированные версии Python и зависимостей для команды; окружение можно создать с чистого компьютера по README.
- Один CLI для подготовки Python, установки и запуска проверок; ручная активация виртуального окружения не требуется.
- Изменения зависимостей видны в PR и воспроизводятся до принятия изменений.
- Одна группа инструментов качества в lock-файле; локальные pre-commit hooks используют те же версии, что ручные команды.

## Недостатки и риски

- uv — дополнительный инструмент, который нужно установить и обновлять у всех участников. Фиксация версии повышает согласованность, но требует сопровождать обновления CLI и Python.
- Первая установка зависит от сети, доступности индекса пакетов и дистрибутива Python. uv использует сборки Astral python-build-standalone; это дополнительный поставщик в цепочке зависимостей. [Источник о дистрибутивах Python](https://docs.astral.sh/uv/concepts/python-versions/#cpython-distributions).
- Lock-файл фиксирует Python-зависимости, но не операционную систему, системные библиотеки или PostgreSQL. Полный запуск приложения и системное окружение нужно проверить отдельно в T-03 и последующих задачах.
- Локальные hooks можно обойти, поэтому они не заменяют человеческое ревью и будущие обязательные проверки CI. CI относится к T-04.
- Аудит `uv audit --locked` в версии 0.13.5 экспериментален и требует сеть; его результаты зависят от актуальности базы известных уязвимостей. Предупреждение не подавляем, проверки запускаем перед PR. [Описание аудита](https://docs.astral.sh/uv/reference/cli/#uv-audit).

## Последствия и проверка принятия

Для нового рабочего места достаточно установить Git и закреплённый uv, клонировать репозиторий и выполнить команды README. `.venv`, кэши и настоящий `.env` не попадают в Git; `.env.example` содержит только безопасные заготовки.

T-02 проверяет окружение и инструменты. Два теста проверяют точную версию Python и виртуальное окружение. pytest-cov и порог 60% подготовлены для будущих `app/` и `bot/`; процент покрытия приложения сейчас не измеряется. С появлением `app/` в T-03 проверяем его покрытие; после появления `bot/` добавляем оба модуля; включение проверки в CI — T-04.
