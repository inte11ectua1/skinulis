# Спецификация роли: ЛЕРА — Telegram UX / integration / QA

## Миссия
Сделать понятные пользовательские сценарии в Telegram, соединить бот с готовым API и обеспечить работающую демонстрацию. Твои задачи самостоятельны и с чёткими входами/выходами; не нужно писать финансовые транзакции PostgreSQL.

## Ownership
bot/**: aiogram handlers, keyboards, FSM dialogue states, httpx API client; mock client/fixture tests, E2E tests UI->API, пользовательский README и сценарий live-demo, UX тексты. Не владеет изменениями моделей/секретов/финансовых функций.

## Спецификация функциональности
1. /start -> согласие пользователя -> create/link profile; показывать причины ошибки без секретов. Не запрашивать пароль.
2. Мои группы/создать/вступить по invite deep-link, список участников.
3. Создание расхода: equal выбрать группу/сумму/участников; custom сумму/точные доли; by_items позиции/цены/участников, итог вычисляет API; предпросмотр + подтверждение.
4. Расходы: листинг с пагинацией, подробности; автор может редактировать/удалять свой расход при наличии API; показывать предупреждение об изменении балансов.
5. Балансы/план; отметка частичной компенсации; входящие pending подтверждение/отклонение; отправитель отменяет pending; кнопки повторно безопасны.
6. Любой HTTP запрос с timeout и явными ошибками 400/401/403/404/409/5xx, без зависания диалога. Стабильный client_request_id сохраняется для retry конкретной операции.
7. FSM состояния доступны в памяти процесса (один polling экземпляр); после рестарта незавершённый черновик можно потерять, но созданные API записи не теряются. Сообщать пользователю, что ввод нужно начать заново.

## UX ограничения
Никакого вычисления долей/балансов локально, только превью от API; не складывать пароли и токены в логи; данные группы не показывать неучастникам; поля пользователя валидировать также на API.

## Acceptance
- Пользователь Telegram проходит /start -> группа -> расход by_items -> баланс -> pending -> confirmed (через другого пользователя); сумма меняется только после подтверждения.
- Бот проверяется с mock API без live Telegram-токена; HTTP-клиент тестируется отдельно.
- Ошибки и отмена диалога понятны; повторные Telegram updates не порождают дубли финансовых записей.
- README и демо-инструкция позволяют человеку провести продуктовую часть защиты.
