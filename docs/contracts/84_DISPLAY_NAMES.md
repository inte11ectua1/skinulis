# #84 — отображаемые имена (merged PR #85)

Расширение T-05/T-06; принципы identity и actor не меняются.

| Контракт | Поведение |
|---|---|
| `users.display_name` | nullable VARCHAR(64); не credential и не уникальный ключ |
| `0007_user_display_name` | после `0006_settlement_notification_claim`; добавляет nullable колонку и CHECK, без переписывания существующих имён/аккаунтов |
| `UserProfile` | прежние поля + `display_name: string \| null`; обычный бот не показывает технические ID |
| `MemberProfile` | прежние user_id/joined_at/is_owner + display_name; только участникам группы, без email/telegram_id |
| `PATCH /users/me` | JWT actor; `{"display_name":"Антон"}` → UserProfile |
| `PATCH /internal/users/me` | проверенные service credential + Telegram actor; тот же DTO/ответ |
| `POST /internal/users/bootstrap` | прежний `{}` остаётся допустим; optional display_name применяется **только при создании**, повтор не перезаписывает имя |

Нормализация: Unicode NFC, внешний trim, 1–64 Unicode code points, запрет категорий C
(управляющие, скрытые форматирующие, суррогаты). SQL CHECK запрещает пустое/длинное,
внешние обычные пробелы и ASCII control. Полная Unicode-проверка — на входе API.
Ошибки 400/401/404/500 в существующем конверте; лишние actor поля запрещены.
Права обновления ограничены текущим actor; auth, Telegram linking, BIGINT PK/FK и
финансовые расчёты не меняются. Production deploy04.11 выполнен отдельным Release41836839608. Read-only SQL follow-up04.11 подтвердил actual head0007; команды миграции не запускались.

Имена — пользовательский текст, HTML всегда экранируется. Telegram full_name берётся
без username только после явного подтверждения создания профиля; при длинном имени
используется безопасный начальный фрагмент до 64 символов. Linking сохраняет прежнее
имя. Старым профилям предлагается «Изменить имя», автоматического backfill нет.

В группе имена длиннее 40 символов сокращаются в подписях. Совпадающие (без учёта
регистра) получают локальные метки «Саша · А», «Саша · Б» по стабильному порядку
членства; при коллизии с буквенной меткой все строки получают уникальный буквенный
префикс. Это не публичный системный ID, не доказательство прав и не уникальный
профиль. На экране участников у текущего actor есть пометка «вы»; участники могут
сверить метку или выбрать разные имена перед финансовым действием. Метки не следует
запоминать вне текущего состава группы. Выбор хранит прежний внутренний user_id.

OpenAPI содержит входные примеры; DTO бота принимает отсутствующее display_name как
null, чтобы читать прежние ответы. Новая функция изменения имени требует нового API.
