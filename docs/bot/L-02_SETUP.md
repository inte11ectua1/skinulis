## Что работает

- `/start` показывает приветствие и стартовое меню, **не создаёт профиль** и не
  объявляет пользователя авторизованным. `/start` с payload сообщает, что
  приглашения пока недоступны; payload не сохраняется и не повторяется в ответе.
- `/help` и кнопка «Помощь» объясняют команды, ограничения и назначение сервиса.
- `/cancel` очищает локальный ввод и возвращает в `Navigation.menu` с пустыми
  данными. Это навигационное состояние, не подтверждение регистрации. Команда
  не отправляет запросы отмены/удаления записей API.
- Повторный `/start` и меню не уничтожают активное состояние будущего диалога:
  показывается подсказка явно отменить ввод через `/cancel`. `/help` сохраняет ввод.
- Кнопки «Мои группы», «Создать группу», «Ожидают подтверждения», «Профиль»
  честно сообщают о недоступности. Повторные нажатия не создают никаких записей.
- «Проверить доступность» выполняет только существующий **GET `/health`**.
  Успех означает доступность сервиса, не регистрацию пользователя.
- Неизвестный ввод/старая кнопка получают безопасную подсказку без цитирования
  входа. В групповых чатах бот просит открыть личный чат. Чужие/недоступные
  callback-сообщения не дают доступа к навигации другого пользователя.

## Подготовка и тесты без токена

Из корня репозитория, с Python 3.12.15 и uv 0.13.5 из инструкции README:

```sh
uv sync --frozen
uv lock --check
uv run pytest tests/unit/test_bot_client.py tests/unit/test_bot_handlers.py tests/unit/test_bot_runtime.py
uv run pytest
uv run pytest --cov --cov-report=term-missing
uv run ruff check .
uv run ruff format --check .
uv run mypy .
uv run pre-commit run --all-files
```

Тестам бота не нужны `.env`, настоящий/заранее записанный фиктивный Telegram-токен,
Telegram Bot API, внешний HTTP API, PostgreSQL или polling. Синтаксический токен
генерируется только в памяти теста; Telegram session полностью заменена AsyncMock.
События поступают в настоящий Dispatcher через `feed_update`, включая FSM/filters.
HTTP использует `httpx.MockTransport`, а проверка совместимости с текущим FastAPI
— `ASGITransport` с заменённой DB dependency, без соединений с PostgreSQL.

В HTTP-fixtures только утверждённый технический ответ `/health` и согласованная
оболочка `error.code/message/request_id`. Искусственные 400/401/403/404/409/5xx
проверяют защиту клиента от ошибочных ответов, а не объявляют новую бизнес-семантику
`/health`. Схем профиля/группы/финансов в mock нет.

`uv run pytest` по принятой конфигурации выбирает unit-тесты и исключает integration.
`--cov` использует существующий source **app + bot**, branch coverage и порог 60%;
не подменяет проверку PostgreSQL. Отдельное покрытие бота при необходимости:
`uv run pytest tests/unit/test_bot_client.py tests/unit/test_bot_handlers.py tests/unit/test_bot_runtime.py --cov=bot --cov-report=term-missing`.
Реальные DB integration запускаются отдельно по README через
`uv run python scripts/test_integration.py --cov --cov-append --cov-report=term-missing`.

На Windows сначала используйте диагностику Python/uv из README. Если `tmp_path`
не может создать системный временный каталог в ограниченной среде, задайте
`PYTEST_DEBUG_TEMPROOT` на отдельную доступную папку своей рабочей области и повторите
команду: проверки не отключать. Не используйте нужные данные как pytest basetemp.

## Запуск реального процесса

Настоящий токен нужен только оператору для реального запуска, **не для L-02 tests**.
Скопируйте `.env.example` в локальный `.env`, не перезаписывая существующий файл,
и заполните токен в редакторе. Значения секретов в команды, Git и логи не вставлять.

| Переменная | Поведение bot/config.py |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Обязательный секрет для запуска. Нет default/фиктивного ключа в коде. Проверяется форма, но не действительность у Telegram; repr и ошибки настройки скрывают значение |
| `API_BASE_URL` | HTTP(S) URL; default `http://localhost:8000`. Для будущего контейнера — `http://api:8000`. Credentials/query/fragment в URL запрещены; URL скрыт из repr |
| `BOT_SERVICE_TOKEN` | Зарезервирован до утверждения UQ-01. В L-02 не читается и не передаётся: публичный `/health` не требует служебной авторизации |

Настройки читают переменные процесса, затем `.env` в текущем каталоге; переменные
API/БД из общего `.env` игнорируются ботом. Backend Settings не импортируются.
Общий `docs/environment-schema.md` описывает T-03; конкретное потребление ботом
переменных в L-02 зафиксировано в таблице выше.

```sh
uv run python -m bot.main
```

API для старта навигации не обязателен: при отказе API проверка доступности выдаёт
безопасное сообщение. Если API уже запущен локально/через основной Compose,
кнопка проверит его текущий `/health`. При неверной конфигурации процесс завершится
с кодом 2 без вывода значения токена; при ошибке выполнения — с кодом 1 и общим
сообщением. Отсутствие токена не исправляется созданием подставного значения.

Запускайте **ровно один polling-процесс для одного Telegram-токена**. Сейчас updates
обрабатываются последовательно (`handle_as_tasks=False`), FSM — MemoryStorage с
SimpleEventIsolation. Состояния и несохранённый ввод не переживают рестарт; финансовых
результатов/ключей операций в этой FSM пока нет. Остановить процесс — `Ctrl+C`
(на Unix также SIGTERM). Контексты закрывают API AsyncClient и Telegram session
при штатном выходе, ошибке и отмене; FSM освобождается в finally.

## HTTP-клиент и безопасность

Один ApiClient/AsyncClient переиспользуется процессом, закрывается через `async with`
или `aclose()`. Интерфейс HealthApi возвращает типизированный HealthResult;
запрос GET `/health` не имеет body. Поля status/database соответствуют текущему
`app/schemas/system.py`; отсутствующий/неожиданный ответ не становится успехом.
Схемы бота не добавляют требований к будущим профилям и финансовым endpoint.

Timeout: connect 3 секунды, read/write/pool по 5 секунд, общий deadline 10 секунд.
Redirects, неявные proxy из окружения и автоматические retries отключены.
Ошибки статуса/timeout/network/формата централизованно преобразуются в ApiError.
Пользователю показывается локальный безопасный текст; сырой message API, URL,
error.code/request_id и traceback не выводятся. Code/request_id сохраняются лишь
как диагностические атрибуты исключения, не входят в str/repr и не логируются.
Сбой уведомления об ошибке также не выводит содержимое исключения.

Бот не импортирует SQLAlchemy, PostgreSQL, модели или денежные функции. В L-02
нет финансовых записей, расчётов, повторов POST и попыток локального превью.
При добавлении записывающих операций нельзя механически использовать текущую
очистку `/cancel`: сначала реализовать различие черновика/запроса в пути/неизвестного
результата и правила UUID из L-01 §7 с согласованным UQ-09.
