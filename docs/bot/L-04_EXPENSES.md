## Создание

В личном чате: `/start` → **Мои группы** → группа → **Добавить расход**.
Бот проверяет доступ к группе и получает все страницы участников. Участники
показаны как `Участник #ID`: имена Telegram других людей API не предоставляет.
Автор/плательщик — текущий проверенный пользователь, он может не входить в потребителей.

| Режим | Шаги |
|---|---|
| Поровну — equal | Название → общая сумма → выбрать участников → «Готово» → серверный предпросмотр → подтверждение |
| Точные суммы — custom | Название → общая сумма → участники → точная доля каждого, включая `0.00` → предпросмотр → подтверждение |
| По позициям — by_items | Название чека → название/стоимость/участники первой позиции → «Готово» → добавить следующие позиции → предпросмотр всего чека → подтверждение |

Денежный ввод — каноническая строка `1250.00`, ASCII, два знака, без запятых,
знаков, внешних пробелов, ведущих нулей и экспоненты. Округления нет. Цена расхода
и позиции положительна; нулевая custom-доля допустима. Диапазон расхода
`0.01..1000000.00`, сумму позиций и точное совпадение custom-долей проверяет API.
Бот проверяет форму поля, не складывает/делит деньги и не исправляет доли.
Названия нормализуются по принятому Q-03: NFC, Unicode strip, 1–120 codepoints,
без category C (включая ZWJ). Некорректный ввод не цитируется в ошибке.

Выбор участников переключается кнопками, есть «Выбрать всех»; пустой выбор не
завершает шаг. У custom при смене состава сохраняются суммы оставшихся, удаляются
исключённые, запрашиваются недостающие. Явные нули сохраняются.

Чек содержит 1–50 позиций, порядок ввода сохраняется. «Изменить/убрать позицию»
позволяет заменить позицию на её прежнем месте либо убрать её. «Назад к черновику»
не добавляет незавершённую позицию. Чаевые/сервисный сбор — отдельные положительные
позиции; отрицательные скидки, проценты и веса не поддерживаются. Root `amount`
для by_items не вводится и не отправляется. Черновик показывает только цены
введённых позиций без общего денежного итога.

## Предпросмотр и изменения

Перед записью бот отправляет business body в API **без UUID и версии**. API
возвращает title, amount, shares и, только для by_items, упорядоченные items/shares.
Выбранные нулевые доли отображаются. Длинные чеки разбиваются на сообщения
до 1800 codepoints, чтобы оставаться в лимите Telegram и для символов вне BMP.
Действующее подтверждение появляется после отправки всех частей предпросмотра.

Предпросмотр не пишет в БД, ничего не резервирует. Любой переход к правке
инвалидирует preview и старую кнопку; сохранение также сравнивает текущий business
body с телом проверенного preview. POST/PUT заново валидируют данные на сервере.
У API нет field-location в ошибке: бот сохраняет поля и предлагает выбрать правку,
не приписывает ошибку конкретной позиции и не угадывает величину расхождения.

В группе **Расходы** открывает сохранённые записи с `{items,limit,offset}`,
по 20, в порядке API. Полная страница предлагает «Далее»; следующая может быть
пустой. Есть возврат назад/обновление, `total` и `has_next` не используются.
Карточка показывает плательщика, сумму, режим, итоговые доли и позиции из API.
У equal/custom `items` отсутствует, включая `null`.

Только автор видит **Редактировать** и **Удалить**; owner не исключение.
Права окончательно проверяет API. Правка перечитывает актуальный расход,
заполняет мастер историческими данными, включая нули, и позволяет изменить все
business-поля. «Сменить режим» предупреждает об очистке несовместимых полей;
выбор нового режима явно очищает суммы/доли/позиции. Разрешены все mode transitions.
Перед правкой, её подтверждением и удалением показано:

> Подтверждённые компенсации сохраняются. Баланс может измениться вплоть до
> обратного долга. Бот не отменяет реальные переводы.

PUT — полная замена с `expected_version`; DELETE — soft-delete с этой версией
в query. 409 требует перечитать карточку и начать правку заново. Старое тело
не перезаписывает новую версию. Ответы PUT/DELETE могут содержать пересчитанные
балансы: бот выводит только эти серверные строки, без самостоятельного расчёта.
Это не отдельный экран балансов/компенсаций L-05.

## Повторы, отмена и восстановление

| Событие | Поведение |
|---|---|
| Первое подтверждение POST | Фиксируются один UUID и JSON business body этого намерения |
| POST timeout/network/5xx/невалидный ответ | Результат неизвестен; только явный повтор исходного запроса с тем же UUID/телом, без автоматической отправки |
| Просмотр списка/карточки после неопределённого POST/DELETE | Исходное намерение сохраняется; есть «К восстановлению запроса». Новое создание/правка временно не предлагаются |
| POST 200 replay | Это исходная envelope, даже после PUT/DELETE; бот перечитывает GET, не показывает исходный snapshot как актуальный |
| POST 409 request_conflict/history_unavailable | Нет обхода новым UUID; чтение сохранённых расходов, отмена/разбор результата |
| PUT timeout/network/5xx | Сначала GET и версия. Неизвестность остаётся честной; чей запрос создал версию, бот не утверждает. После чтения — новая правка, без автоматического PUT |
| Ошибка чтения после PUT timeout | Сохраняется контекст и кнопка повторного чтения, второй PUT не отправляется |
| DELETE timeout/network/5xx | Явный повтор того же ID/старой версии. Backend сохраняет tombstone/version; stale первый DELETE всё равно даст409 |
| 400 | Сохраняется ввод, доступны правки и новое preview; суммы/состав проверяет сервер |
| 401/403/404 | Безопасный отказ, без password/JWT и сведений о чужом объекте |
| Двойной callback/старое preview | Nonce текущего экрана, инвалидируемый до dispatch; повтор не пишет |
| Повтор update | Существующий L-03 bounded dedup в памяти, API UUID/version остаются окончательной защитой |
| `/start`, `/help` в мастере | `/start` предлагает продолжить/отменить, `/help` не стирает ввод |
| `/cancel` на любом шаге | Очищает весь FSM, включая UUID. Не отменяет уже отправленный запрос/сохранённую запись, предупреждает о неизвестном результате |
| «Отменить расход» | Отдельное подтверждение очистки черновика; без POST/PUT/DELETE |
| Рестарт процесса | MemoryStorage/UUID/черновик могут потеряться; старые кнопки отвергаются. Сначала проверить список; автоматического восстановления/нового POST нет |

Одна polling-инстанция, SimpleEventIsolation и последовательная обработка
сохраняются из L-03. Дедуп 4096 update IDs не является durable-хранилищем.

## API и запуск

Используется существующая [конфигурация L-03](L-03_SETUP.md), новые зависимости
или секреты не нужны. `TELEGRAM_BOT_TOKEN`, отдельный `BOT_SERVICE_TOKEN` —
только окружение; `.env.example` не содержит значений секретов. API должен быть
настроен и мигрирован его владельцем; бот не запускает миграции и не подключается к БД.
Не запускайте реального Telegram-бота или ручной live E2E до отдельного разрешения Тимура.

| Метод | Принятый путь |
|---|---|
| POST | `/internal/groups/{group_id}/expenses/preview` |
| POST / GET | `/internal/groups/{group_id}/expenses` |
| GET / PUT | `/internal/expenses/{expense_id}` |
| DELETE | `/internal/expenses/{expense_id}?expected_version=N` |

Типизированный httpx-клиент сохраняет connect timeout3s, read/write/pool5s,
общий deadline10s, закрытие через async context, без автоматических retries/redirects.
Заголовки только `X-Bot-Service-Token` и `X-Telegram-ID` из `Update.from_user.id`.
Actor/payer/author не входят в финансовый JSON; JWT в Telegram не используется.
Raw error.message/traceback/credentials не выводятся и не логируются.

старые/двойные callbacks/update, отмену/рестарт, безопасные ошибки/логи.
Используются только созданные в памяти значения, настоящие credentials не нужны.
DTO/fixtures сверяются с реальными backend-моделями и OpenAPI.

`tests/integration/test_bot_expenses.py` использует существующий fixture,
создающий отдельную UUID-БД с миграциями на PostgreSQL17. Настоящий Uvicorn,
loopback HTTP, обычный ApiClient; заменена только Telegram session. Специальный
transport теряет один реальный ответ **после commit** для проверки восстановления.
Проверяются все режимы, no-write preview, ресторанные доли, точные нули,
чужой actor404/member403, edit/mode switch/version/soft-delete и реальные повторы.

При отсутствии Docker допустим существующий путь с `TEST_DATABASE_URL` к отдельному
PostgreSQL17: bootstrap имя заканчивается `_test`, роль CREATEDB, случайный пароль
через безопасное окружение. Затем `uv run coverage run --append -m pytest -m integration`.
Не использовать пользовательскую БД, не удалять чужие volumes. Fixture удаляет
только собственные UUID-БД. Точные результаты текущего head фиксируются в PR.
