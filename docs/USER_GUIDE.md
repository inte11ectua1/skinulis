# Пользовательская инструкция «Скинулись»

Сервис записывает совместные расходы и ручные компенсации. Он не переводит деньги,
не проверяет банк и не подтверждает получение за другого участника.
Основной интерфейс — личный чат с Telegram-ботом. Эта инструкция описывает код
`main` после M5; production может содержать предыдущую версию. Live polling пока
выключен: для демонстрации его нельзя включать без отдельного разрешения Тимура.
[Проверенные offline-сценарии и ограничения](reviews/M6_ACCEPTANCE_REPORT.md).

## Начало и профиль

1. Откройте личный чат, отправьте `/start`.
2. Если профиля нет, выберите **Создать профиль** → **Да, создать**. Email и пароль
   не нужны. До согласия аккаунт не создаётся.
3. Если уже зарегистрированы через API, выберите **Привязать существующий аккаунт**.
   В своём API-аккаунте войдите через `/auth/login`, получите JWT и выполните
   `POST /users/me/telegram-link-code` с `{}`. Передайте боту только выданный код:
   он действует 10 минут и используется один раз. Пароль и JWT в Telegram не отправляйте.
4. **Профиль** показывает текущую запись. Слияния двух существующих профилей нет:
   если нужен прежний API-аккаунт, не создавайте сначала новый Telegram-only профиль.

`/help` показывает справку. `/cancel` очищает несохранённый ввод, но не отменяет
уже совершённую запись API. После перезапуска черновик может потеряться; сначала
проверьте сохранённые группы/расходы/переводы.

## Группа и два приглашения

**Создать группу** → название → **Создать**. Название: 1–120 символов, внешние
пробелы убираются, управляющие символы запрещены. Создатель становится владельцем
и первым участником. **Мои группы** → карточка показывает доступные действия.
Другие пользователи не видят эту группу до добровольного вступления.

Владелец открывает **Приглашения** → **Создать приглашение**, затем подтверждает
создание. Полученную ссылку вида `https://t.me/<bot>?start=i_<secret>` передаёт
одному человеку приватно. Участник открывает её, выбирает/создаёт профиль, затем
**Вступить**. Для второго человека нужна отдельная ссылка: каждая одноразовая,
действует 24 часа. Не публикуйте ссылки в отчётах и скриншотах.

Владелец может отозвать неиспользованное приглашение в его карточке. Использованное
отозвать нельзя. Потерянный секрет нельзя восстановить из списка. После неизвестного
результата выдачи сначала перечитайте приглашения: если raw-ссылка потеряна, отзовите
запись и только затем явно создайте новую. В группе максимум 30 человек.
Участники/группы не удаляются, владелец не передаётся в MVP.

## Расходы

Карточка группы → **Добавить расход**. Плательщик и автор — текущий пользователь;
нельзя записать платёж от имени другого. Потребители могут быть подмножеством группы,
в том числе без плательщика. API показывает участников как **Участник #ID**:
сопоставьте ID профилей перед вводом.

Сумма вводится как `1250.00`: точка, два знака, без пробелов, запятой или экспоненты.
Диапазон одного расхода — `0.01`–`1000000.00` ₽. Расчёт ведётся в целых копейках.

| Режим | Что вводить | Пример |
|---|---|---|
| **Поровну — equal** | Название, общую сумму, потребителей, **Готово** | `100.00` на троих: `33.34`, `33.33`, `33.33`; копейка первому по внутреннему ID |
| **Точные суммы — custom** | Название, сумму, потребителей, точную долю каждого | `10.00`: `0.00`, `3.33`, `6.67`; сумма долей должна совпасть точно |
| **По позициям — by_items** | Название чека; название, цену и потребителей каждой позиции | Паста `700.00` одному, пицца `900.00` троим; общую сумму вычисляет API |

У чека 1–50 позиций. Чаевые/сервис — отдельная положительная позиция; отрицательных
скидок, процентов и весов нет. **Добавить позицию** продолжает чек, **Изменить/убрать
позицию** исправляет его. Для custom допустима нулевая доля, для цены позиции — нет.

Нажмите **Серверный предпросмотр**, проверьте сумму/доли, затем **Подтвердить расход**.
Предпросмотр не сохраняет расход и не резервирует баланс. Правка черновика требует
нового предпросмотра; старая кнопка не действует.

Через список расходов откройте карточку своего расхода для редактирования/удаления.
Другой участник, даже владелец, не может изменить чужой расход. Удаление мягкое:
история сохраняется. При подтверждённых компенсациях правка может создать обратный
долг; реальные подтверждённые переводы остаются учтены. Сначала прочитайте предупреждение.

## Балансы и рекомендации

**Балансы**: плюс — участнику должны, минус — участник должен. Ноль — нет долга.
Сумма балансов группы строго ноль. **План переводов** предлагает, кому и сколько
перевести; просмотр ничего не записывает, минимальное число переводов не обещается.
Результат меняется при новых расходах/подтверждениях.

## Переводы и подтверждение

Только после реального внешнего перевода отправитель выбирает **Я перевёл деньги**,
получателя и сумму, затем **Да, я уже перевёл деньги**. Создаётся `pending`:
балансы пока не изменились. Частичный перевод разрешён — например, `500.00` из `1400.00`.

Получатель открывает **Ожидают подтверждения** → группа → **Открыть перевод #ID**.
**Подтвердить получение** → **Да, деньги получены** нужно нажимать только после
фактического получения. После `confirmed` баланс обновляется один раз.
Best-effort уведомление может не прийти: проверяйте это меню самостоятельно.

| Действие | Кто может | Результат |
|---|---|---|
| Подтвердить получение | Указанный получатель | `confirmed`, влияет на баланс, окончательно |
| **Отклонить** → **Да, отклонить** | Получатель | `rejected`, не влияет на баланс |
| **Отменить заявку** → **Да, отменить заявку** | Отправитель pending | `cancelled`, не влияет на баланс |

**История переводов** и **Исходящие переводы** показывают состояние. Владелец группы
не может подтвердить чужую компенсацию. Terminal-статусы не редактируются.
Если долг изменился, confirm может вернуть 409: запись остаётся pending, её можно
отклонить или отменить; сервер не исправляет сумму автоматически.

## Ошибки и неизвестный результат

| Ситуация | Безопасное действие |
|---|---|
| Невалидная сумма/состав, HTTP 400 | Исправить поля, запросить новый preview; неверный ввод не означает сохранение |
| 401 | Проверить доступность/конфигурацию через ответственного; пароль/JWT боту не отправлять |
| 403 | Проверить свою роль: приглашает owner, правит автор, подтверждает receiver |
| 404 | Проверить свои группы/историю; чужой/скрытый объект не раскрывается, не перебирать ID |
| Истёкшая/использованная ссылка | Попросить owner создать новую; не пытаться вступить за другого |
| 409 версии расхода | Перечитать карточку, проверить изменения, сделать новый preview; не перезаписывать вслепую |
| 409 UUID | Прочитать историю: UUID связан с другим намерением; не выдавать автоматически новый ключ |
| Timeout/сеть/500 после POST | Запись могла сохраниться. Проверить список/карточку; использовать предложенное восстановление и **Повторить исходный запрос** только с прежними UUID/body |
| Timeout после confirm/reject/cancel | Прочитать актуальный status; повторять то же действие только через экран восстановления; не создавать новый перевод |
| Потеря черновика/перезапуск | Сначала проверить сохранённые данные; `/cancel` не отменяет commit, старые кнопки недействительны |
| HTTP 429 | Выждать и повторить явно; автоматического финансового повтора нет |

Replay создания может вернуть исторический `pending` или первоначальную версию расхода.
Это подтверждение первоначального запроса, а не текущего состояния: перечитайте GET.
При восстановлении привязки проверьте и **Профиль**, и `/users/me` прежнего API-аккаунта:
одно наличие Telegram-профиля ещё не доказывает, что привязан нужный аккаунт.

[Пошаговый сценарий трёх пользователей](reviews/M6_THREE_USER_DEMO.md) использует
только синтетические данные и не предполагает реальных банковских операций.
