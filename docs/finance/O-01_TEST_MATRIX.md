# O-01 — матрица будущих финансовых тестов

Статус: чек-лист для ревью [Issue #3](https://github.com/inte11ectua1/skinulis/issues/3). Это спецификация ожидаемых результатов, а не выполненные unit/integration/concurrency tests.

Уточнение 26.10.2026: [Тимур утвердил Q-01/Q-02 и подтвердил границы Q-04](https://github.com/inte11ectua1/skinulis/issues/11#issuecomment-6425832067). M-014/M-015/M-016/E-008 имеют определённые unit-ожидания. Галочки остаются снятыми: HTTP/integration-части будущих этапов не считаются выполненными из-за unit-проверок.

## Обозначения и фикстуры

- Все числовые суммы в таблицах — **копейки**, кроме явно заключённых в кавычки API-строк рублей. `B=(...)` — полный вектор балансов в указанном порядке; отсутствие доли математически означает 0, представление нулевых строк — Q-10.
- `G={10,20,30}`, `10<20<30` — синтетические ID. `40` — посторонний, если явно не добавлен в группу. Actor доверенный; обычный расход создаёт и оплачивает один actor. Внутренний тип по Q-02: положительный Python int в signed BIGINT, не bool; сериализация API отдельно ожидает согласования.
- **R**: ресторан из [инвариантов §4](O-01_INVARIANTS.md#restaurant), actor/payer 10; доли `(100000,140000,80000)`, `B=(220000,−140000,−80000)`.
- **S**: расход 100 оплатил 10, единственный потребитель 20; `B=(+100,−100,0)`.
- **U/I/C**: будущий unit/integration/concurrency test. `U+I` означает отдельно проверить pure function и HTTP/DB-границу на соответствующих этапах; HTTP-статус не является результатом unit-функции.
- **+ / − / ±**: положительный / отрицательный / смешанный сценарий.
- `—` в HTTP — неприменимо; `успех Q-07` — данные и эффект определены, точный success-код требует решения; `TBD(Q-xx)` — конкретный ответ пока нельзя утверждать.
- Все API-ошибки имеют согласованную оболочку `error.code/message/request_id`; конкретные коды ошибок — Q-07. Негативный запрос не меняет финансовые записи и балансы.
- Инварианты INV-* определены в [O-01_INVARIANTS](O-01_INVARIANTS.md); Q-* — в [O-01_OPEN_QUESTIONS](O-01_OPEN_QUESTIONS.md).

Ссылки на требования: **PR** = [PRODUCT_RULES](../PRODUCT_RULES.md), **TD** = [TECHNICAL_DECISIONS](../TECHNICAL_DECISIONS.md), **B** = [BOUNDARIES](../contracts/BOUNDARIES.md), **OS** = [OLEG_SPEC](../roles/OLEG_SPEC.md). В каждой строке указан раздел источника. `[ ]` отмечается только после появления и запуска соответствующего теста на указанном этапе, а не после принятия O-01.
